Native OAuth 2.0 authorization-code + PKCE for Android and iOS via the
`flet-appauth` extension.

`AppAuth` performs **authorize + redirect capture only**. Token exchange,
user/group loading, and `Page.on_login` remain in Python (`Page.login` /
[`AuthorizationService`](../../types/auth/authorizationservice.md)).

On **Android**, authorize uses Chrome [Auth Tab](https://developer.chrome.com/docs/android/custom-tabs/guide-auth-tab)
when available so custom-scheme redirects are returned to the app via
callback. If Auth Tab is not supported, it falls back to a full external
browser (not a Custom Tab). On **iOS**, authorize uses
[`flutter_appauth`](https://pub.dev/packages/flutter_appauth) /
ASWebAuthenticationSession.

On Android/iOS, `page.login()` soft-imports this package automatically.
Install it before calling `page.login` on mobile.

**`flet run` on a stock Flet Android/iOS client** does not include this
extension. Use a packed app (`flet build apk` / `ipa`) that depends on
`flet-appauth`, or a custom Flutter client that registers the plugin.

### Build redirect scheme

When `flet-appauth` is a dependency and you do not set a scheme, `flet build`
derives one from your app name in `pyproject.toml` (first match wins):

1. `tool.flet.project`
2. `tool.flet.artifact`
3. `tool.flet.product`
4. `project.name`

The value is sanitized to a URL scheme (lowercase; letters, digits, `+`, `-`,
`.`). If nothing usable remains, the fallback is **`flet`**.

:::note
[`page.title`][flet.Page.title] cannot drive the scheme. The Android/iOS
project files are patched at **build** time, before the app runs.
:::

`flet build` / `flet debug` always logs the chosen value, for example:

```text
AppAuth redirect scheme: appauth (from app name (tool.flet.project='appauth' -> appauth))
```

Use that scheme in your IdP callback URI and
`OAuthProvider.redirect_url` (e.g. `appauth://oauth-callback`).

Override when needed (not [`tool.flet.deep_linking`](../../publish/index.md#deep-linking)):

```toml
[tool.flet.appauth]
redirect_scheme = "myapp"
```

Or:

```bash
flet build apk --appauth-redirect-scheme myapp
```

Resolution order: CLI → platform `tool.flet.<android|ios>.appauth` →
`tool.flet.appauth` → app name → `flet`.

See [Publishing — AppAuth redirect scheme](../../publish/index.md#appauth-redirect-scheme-oauth--flet-appauth).

PKCE on mobile is generated by AppAuth. Provider `code_verifier` /
`code_challenge` fields are for **web** only and are ignored on Android/iOS.

Web-only `page.login` parameters (`on_open_authorization_url`,
`complete_page_html`, `redirect_to_page`) are ignored on mobile.

## Auth0 native (PKCE) on Android / iOS

Use an Auth0 **Native** application (public client). Do **not** put a
client secret in a packaged APK/IPA.

### 1. Create a Native application

In Auth0: **Applications → Create Application**. Choose **Native**, then
**Create**.

<Image src="/docs/assets/services/appauth/auth0-create-native.png" width="85%" caption="Create a Native Auth0 application" />

### 2. Copy Domain and Client ID

Open the app **Settings** tab. Copy **Domain** and **Client ID** into your
app env (see below). Leave the client secret unused — this is a public
native client.

<Image src="/docs/assets/services/appauth/auth0-settings-credentials.png" width="85%" caption="Domain and Client ID on the Settings tab" />

### 3. Register callback URLs (URLs tab)

Open the **URLs** tab (not Settings). Add the same URI to **Allowed Callback
URLs** and **Allowed Logout URLs**. It must match your AppAuth redirect
scheme and `OAuthProvider.redirect_url` (see [Build redirect
scheme](#build-redirect-scheme)).

For the packaged example (`tool.flet.project = "appauth"`):

```text
appauth://oauth-callback
```

<Image src="/docs/assets/services/appauth/auth0-urls-callbacks.png" width="85%" caption="Allowed Callback / Logout URLs on the URLs tab" />

### 4. Configure the Flet app

Set env vars (recommended: `python-dotenv` + `.env` next to `main.py`):

```text
AUTH0_DOMAIN=your-tenant.us.auth0.com
AUTH0_CLIENT_ID=your-native-app-client-id
# AUTH0_REDIRECT_URL=appauth://oauth-callback   # optional override
```

Package `.env` — it is a **default exclusion** (dotfile). Keep it with
`include` or `--include`:

```toml
[tool.flet.app]
path = "src"
include = [".env"]
```

```bash
flet build apk --include .env
```

`flet build` warns when `.env` matched a default exclusion and was skipped.

+ `include = [".env"]`). Gallery snippet:
